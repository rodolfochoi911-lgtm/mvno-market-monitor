# 디시 행사글 Teams 알림

기존 커뮤니티 모니터링이 운영되는 `mvno-market-monitor`에 독립 워크플로를 추가했다.
`competitor-monitor`는 경쟁사 사이트 수집 및 Slack 전송 저장소이므로 수정하지 않는다.
일간 워크플로, 수집/분석, JSON/XLSX, 대시보드 기능은 변경하지 않는다.

## 실행과 메시지

- `DC event alerts (10 minutes)`는 매시 03/13/23/33/43/53분(UTC)에 실행한다.
  GitHub Actions 예약은 지연/누락될 수 있어 정확히 10분 이내 도착을 보장하지 않는다.
- 목록: `https://gall.dcinside.com/mgallery/board/lists/?id=mvnogallery&sort_type=N&search_head=120&page=1`
- `scripts/monitor_crawler.py`의 기존 `send_slack_message`가 보내던 Teams Adaptive Card
  전송을 `scripts/teams_notifier.py`로 분리해 일간/행사 알림 모두 재사용한다.
  기존 `COPILOT_WEBHOOK_URL` secret을 그대로 사용한다. 새 비밀키는 필요하지 않다.
- 제목, 본문 핵심 문장(가격/혜택/기간/조건 우선), 원문 URL을 최대 5건씩 묶는다.
  본문 요약은 원문 문장을 골라 압축하며 LLM/API 비용이 없다.
  이미지 본문은 OCR을 수행하지 않고 원문 이미지 확인 안내를 표시한다.
- Selenium/Chrome, pandas, 일간 데이터, 메일 전송을 실행하지 않는다.
  변경 없는 실행은 디시 목록 요청 1회, 상태 읽기 1회만 수행하고 상태를 쓰지 않는다.

## 중복 방지와 실패 처리

- 전용 `dc-event-state` 브랜치의 `state/dc_events.json`에 상태를 저장한다.
  일간 데이터가 있는 main에는 상태 커밋을 추가하지 않는다.
  Actions 기본 `GITHUB_TOKEN`의 contents:write 권한으로 생성/갱신한다.
  저장소 브랜치 규칙이 브랜치 생성/쓰기를 제한한다면 해당 권한을 허용해야 한다.
- 첫 실행은 최신 행사 게시글 ID를 기준선으로 기록하며 과거글/본문을 전송하지 않는다.
  상태 파일이 삭제되면 현재 목록으로 다시 기준선을 잡고 알림하지 않는다.
  손상된 상태나 상태 조회 실패는 덮어쓰거나 초기화하지 않고 실행에 실패한다.
- 완료 기준선 이하 게시글 ID는 영구 제외한다. 기준선보다 큰 새 ID만 대상이다.
  기존 글을 수정하거나 과거글 말머리를 행사로 바꾼 경우는 알림 대상이 아니다.
- 새 글이 많으면 기준선까지 페이지를 추가 조회한다(최대 10페이지).
  페이지 반복/한도 초과/다른 말머리/구조 변경/본문 삭제/네트워크 실패는 알림 전
  중단하며 기존 seen 상태를 보존한다. 모든 대상 본문을 먼저 검증한다.
- GET과 행사 Teams 전송은 최대 3회, 1/2초 간격으로 재시도한다.
  Teams 전송은 429/5xx/연결 오류에만 재시도하며, 4xx/리디렉션/알려진 HTTP 200
  오류 응답은 실패 처리한다. 일간 전송의 시도 횟수는 기존처럼 1회다.
- Teams HTTP 2xx 수신 확인 후에만 해당 묶음의 ID를 저장한다.
  다음 묶음 전송에 실패하면 이미 확인된 묶음은 재실행에서 제외한다.
  상태 갱신은 기존 contents SHA를 사용하며 충돌 시 덮어쓰지 않는다.
- 웹훅 202는 비동기 워크플로의 수신 확인이며 Teams 채널 표시 완료 확인은 아니다.
  전송 후 응답 유실 또는 상태 저장 실패/프로세스 종료는 재실행 중복 가능성이 있다.
  웹훅에는 수신측 중복 키가 없어 exactly-once 전송을 보장할 수 없다.
  이때 오류를 숨기지 않고 실패하며 운영자는 Actions와 Teams Workflows 이력을 확인한다.
  원본 requests 예외, 응답 본문, 웹훅 URL, 토큰은 로그에 출력하지 않는다.

## 검토 및 운영

PR을 main에 병합하면 예약이 활성화된다. 처음 정상 실행은 기준선만 생성한다.
Actions에서 수동 실행할 때 `dry_run` 기본값은 true다: 메시지 미리보기만 출력하며
Teams 전송/상태 생성/갱신을 수행하지 않는다. 정상 동작을 수동 실행하려면 false를 선택한다.
실패한 실행을 재실행하면 저장된 상태에서 이어간다. 상태 브랜치는 삭제하지 않는다.

검증: `python -m unittest discover -s tests -v`
실제 행사 목록 10건 및 게시글 509647 본문 구조를 읽기 확인했다(2026-10-08 KST).
Teams 실전송은 실행하지 않았으며 비밀키를 조회하지 않았다.
